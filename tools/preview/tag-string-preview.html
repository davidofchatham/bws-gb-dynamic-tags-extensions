✅ SHIPPED 1.17.0 — this tool is no longer the authority
The grammar SHIPPED (2026-08-03/04) and its owners are the authority now: includes/helpers/slot-fold.php (PHP) and assets/js/slot-fold-grammar.js (its tested twin). This page stays as the EXPLORATION surface — comparing candidate spellings side by side is what it is for, and that job outlives the decision.

Three things shipped differently from the bullets below, so read them as design history:
• No N- siblings in the shipped containers. Everything a slot owns rides INSIDE its N: value — label folded in, link inlined, sep HELD (still open). The sibling model here is a live option for later carriers, not what join/try_ emit.
• Folded slot keys are CAPITALS (A:, B:, …), and rank came back to the sort with them: format leads again, then the tag-level source, then the slots ascending. Digits were the FIRST cut and never shipped in a release — an all-digit key is a JS array-index property, which ECMAScript enumerates before every string key, and GB serializes with Object.entries(), so digit slots were PINNED to the front and no sort could move them. Escaping that pin is the whole reason the keys are letters. The digit radio below stays as a look-back.
• + and / are RESERVED, not merely rejected: they are ordinary CONTENT inside a value and are NOT leniently accepted as grammar, because a lenient class spends the char — binding one later would silently change what saved wires mean. The pickers still offer them, as an exploration tool should.

✅ SETTLED 2026-08-04 — folded slot KEY spelling
Built first as 1:, re-spelled to A: before 1.17.0 shipped. An all-digit key is a JS array index, which ECMAScript enumerates ahead of every string key, and GB serializes with Object.entries() — so digit slots were PINNED to the front of the saved string and no sort could move them. A spelling that is not an array index hands rank back to the canonical order, which is what 1.17.0 does: format leads again. Verified NOT blocked: GB's parse_options() preserves key case verbatim.
Where to look: join — TEMPLATE MODE and the table groups. Those are the folded scenarios that carry tag-level options (format:, valueSep:, src:, caption:). Under digits those options are FORCED behind the slots; under a non-index spelling they lead. Groups with no tag-level option show only the key changing, which is why the ordering question was invisible on this page until the join formats were added.
Tokens follow the keys (user 2026-08-04). Template mode addresses slots as %1…%10 on the wire (brace tokens are impossible — GB's parser rejects } inside options), and that ordinal was only ever the digit one, so it moves with the spelling: under capitals the author reads A: beside %A, ONE alphabet rather than two. Formats are authored in digit form and rewritten by formatTokens(), so this picker moves keys and tokens together.
Digit tokens stay readable as a FALLBACK, which is what makes the move migration-free: bws_join_wire_format() maps both alphabets onto the same internal {N}, so every stored format:%1 (%2) keeps rendering and no converter entry is needed. The cost shows in the %% row — while both alphabets are live, the literal-percent escape widens from "before a digit" to "before a digit or a SLOT LETTER". The letter class is A-Z, not A-J (user 2026-08-04): the cap is a CONTAINER property (join 10, try_ 5), so baking today's join limit into the grammar would mean re-cutting it whenever a container changes. The tokenizer still only rewrites as far as that container's slot count, so %K stays literal in a 10-slot join.
s1: is rejected twice over: s names nothing, and the word form it implies (slot1…slot10) MIS-SORTS under any string comparator (slot1, slot10, slot2), so it would need a numeric-aware sort in both serialization-order.php and its JS port. A…J sort right for free.
Still not modelled here: panel LABELS — this page renders wires only. They DID move with the keys ("Slot B", "Field B"), because leaving them as digits just relocates the mapping tax into the editor. bws_slot_ordinal() shipped as the single owner of digit→letter for keys, labels and tokens alike; a {N}- SIBLING key keeps its digit, and so does {{table}}'s "Column 2 Header", since nothing pins their order.
